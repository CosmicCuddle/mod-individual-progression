## Follow-on S1 child — saved-COMPLETE login deferral (2 November 2026)

**Implementation:** In existing paid PlayerScript `OnPlayerLogin`, **after** grandfather evaluation and **before** the reminder, only when paid mode ON + normal account + no TBC entitlement + quest status exactly COMPLETE, call Core `IncompleteQuest(10259)`. That Core method keeps the quest, objective/kills and reward history, clears COMPLETE status in quest log, and marks quest status for persistence. It is not `RemoveQuest`, a quest reset, a progression change or a money transaction. One client warning and a character-GUID-only server log note explain the deferral. On the next paid kill/normal quest completion, the pre-completion hook can allow a legitimate turn-in. OFF, bots, already paid, start-stage privileged and REWARDED remain untouched. No new config, SQL, hooks or Core edits.

**Residual blockers:** No hook can prevent a direct **offline GM `.quest reward`** DB write; an operator restriction is necessary but cannot be enforced by this IP code. Require **restart for paid feature activation** instead of assuming config reload covers characters already in-world. The source test mirrors the exact guard but is not proof of a live client quest-log refresh or a transaction-safe save. Before any live changes: owner-approved staging, real quest10259 states, backups/rollback, latest combined native build and gameplay acceptance. **Feature OFF / DRAFT; not ready to enable.**

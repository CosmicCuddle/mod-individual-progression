## Exact source-derived blocker

The new optional actor and WHO viewer adapter in IP139 checked `isGMAccount(ordinaryViewer)` and `isNormalAccount(ordinaryViewer)` after authenticated normal session security. In real existing IP `src/IndividualProgression.cpp`, both call `GetAccountMatch(accountId)`. Although `GetAccountMatch` uses `_accountMatchCache` protected by `std::shared_mutex`, **on a cache MISS it calls blocking `AccountMgr::GetName` and `AccountMgr::GetSecurity` login/Auth database queries**. Core6 visibility checks may occur in map traversal or WHO/session threads; an unknown/new viewer must not pause those workers to query a database for the optional F14 concealment decision. This is a verified source-path hazard, **not evidence that IP139 was enabled or stalled an actual server**.

Existing IP `PlayerScript::OnPlayerLogin` calls `isNormalAccount(player)` for normal login when enabled and in world, which normally warms its classification cache on the login path. This does **not guarantee** the entry remains present after config reload, failed login, or an unusual session; unknown is explicitly **not human proof**.

## Narrow new opt-in-only behavior

- **Opt-in guarded IP class method:** `TryReadF14CachedNormalHumanAccount(uint32 accountId)` under exactly the existing `COSMIC_IP_F14_CORE6_POSITIVE_RNDBOT_VIEWER_POLICY_EXPERIMENT>=1` compile gate, declared in `src/IndividualProgression.h` and implemented in `src/IndividualProgression.cpp`. Acquires a shared lock once, looks up the existing `_accountMatchCache` and returns true **only** if a present entry has `!excluded && !bot && !gm`. Unknown, zero, flushed or invalidated cache returns FALSE/visible. It **never calls `GetAccountMatch` or the Auth DB**, writes cache, resolves a username, grants stage, or alters any established account classification.
- **Optional adapter only:** `IndividualProgressionF14Core6PositiveRndbotAdapter.h` preserves `AccountMgr::IsPlayerAccount(currentSessionSecurity)`, existing GM-mode, non-headless, in-world, not-self and IP verified current-login GUID/account/race/epoch checks. Replaces potentially blocking `isGMAccount` and `isNormalAccount` with the single cache-only positive check **before** `GetEffectiveProgression`. No WHO target dereference or additional manager lookup.
- **Original source:** `IndividualProgressionPlayer.cpp` and its FALSE-only Core6 adapter, `GetAccountMatch` behavior for all existing non-F14 paths, cached regular group/paid/Hunter logic and actual default OFF configs remain **byte-identical to IP139**. Only the new optional reader method's guarded insert changes `IndividualProgression.cpp`; deleting that insert reconstructs the original IP137/IP139 file byte-for-byte.
- **Unknown safety:** a missing cache entry is fail-*visible*; after reload, a viewer may temporarily continue seeing a selected RNDbot even if a later approved visibility system might otherwise conceal it. This is intentional, not permission to force account identity or visibility refresh. It never hides a human/Altbot/GM because the cached result alone does not identify a target.
